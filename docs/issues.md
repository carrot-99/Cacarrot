# 課題と不足している機能

2026-11-16 時点の実装をもとにまとめています。優先度の目安は次のとおりです。

| 優先度 | 意味 |
| --- | --- |
| 高 | リリース前に必要 |
| 中 | 使い勝手に大きく関わる |
| 低 | あるとよい |

## 1. リリース前に必要なこと（優先度：高）

| # | 内容 | 補足 |
| --- | --- | --- |
| H1 | **AniList のデータと画像を使ってよいか確認する** | AniList の API 規約では、商用利用に制限があります。同梱したあらすじと表紙画像の権利は、出版社や作者にあります。規約を確認し、使えない場合は別のデータ源（出版社の API、書影 API など）を検討してください |
| H2 | **プライバシーマニフェスト（PrivacyInfo.xcprivacy）がない** | Firebase Analytics を組み込んでいるため、App Store の審査で必要です。App Privacy の申告も必要です |
| H3 | **`GoogleService-Info.plist` がないとアプリが落ちる** | Git の管理外なので、クローンしただけではビルドしても起動時に落ちます。ファイルがないときは `FirebaseApp.configure()` を呼ばないようにするか、設定方法をチームで共有してください |
| H4 | **Git リポジトリになっていない** | まだ `git init` していません。バックアップは `backup-2026-11-15/` だけです |
| H5 | **テストがない** | テストターゲット自体がありません。最低限、`SwipeDeckViewModel.action(for:)`（しきい値の判定）、`undo` / `forget` / `restoreSkipped`、`SwipeHistoryStore`、`build_app_data.py` の `is_japanese_title` と `clean_description` に単体テストを追加してください |

## 2. データの課題

| # | 優先度 | 内容 | 補足 |
| --- | --- | --- | --- |
| D1 | 中 | **あらすじが英語、作者名がローマ字** | AniList のデータが英語のためです。日本語のあらすじが取れるデータ源に移るか、翻訳したものを同梱する必要があります |
| D2 | 中 | **中国の作品が少し混じる**（19天、長歌行 など） | CSV に国の情報がないため、タイトルの文字で判定しています。`query.py` で `countryOfOrigin` も取得し、`JP` で絞り込むのが確実です |
| D3 | 中 | **作者が「スタッフの 1 人目」** | 原作者と作画者を区別していません。`staff.edges.role` を取得して、Story / Art で選ぶようにしてください |
| D4 | 中 | **表紙が毎回ネットワークから読み込まれる** | `AsyncImage` は URLCache 任せで、オフラインでは表示されません。画像キャッシュ（Nuke / Kingfisher など）を導入し、次のカードの画像を先に読み込むようにしてください |
| D5 | 低 | **お気に入りのデータが古くなる** | `SwipeRecord` は判定したときの作品情報のコピーを持っています。`manga.json` を作り直しても、お気に入り一覧は更新されません |
| D6 | 低 | **以前のサンプル（ID 0〜5）の履歴が残る** | 実データに切り替える前に判定した ONE PIECE などが、お気に入りに残っています。マイページのリセットで消えます。リリース時は関係ありません |
| D7 | 低 | **データの更新にアプリの再リリースが必要** | 作品はアプリに同梱しています。新しい作品を届けるには、Firestore などのリモートの取得元（`MangaRepository` の別実装）が必要です |
| D8 | 低 | **`query.py` の再開ページを手で書き換える** | `start_page = 1995` がコードに直接書かれています。最後に取得したページをファイルに保存し、引数で指定できるようにすると安全です |
| D9 | 低 | **ジャンルの日本語訳が一部だけ** | `GENRE_JA` にないジャンルは英語のまま表示されます |

## 3. 実装の課題

| # | 優先度 | 内容 | 補足 |
| --- | --- | --- | --- |
| I1 | 中 | **取り消し履歴が保存されない** | アプリを再起動すると、直前の判定を取り消せません。`SwipeRecord.createdAt` の新しい順から作り直せば対応できます |
| I2 | 中 | **保存の失敗に気づけない** | `SwipeHistoryStore.save()` は、デバッグ時に `assertionFailure` を出すだけです。本番ではエラーが無視されます |
| I3 | 低 | **判定の文字列 `"nope"` が直接書かれている** | `#Predicate` で enum を使えないため、`ContentView` と `LibraryView` に `"nope"` と書いています。定数にまとめてください |
| I4 | 低 | **マイページの集計を毎回すべての履歴で計算している** | 判定が数千件になると重くなる可能性があります。`fetchCount` を使うか、集計結果をキャッシュしてください |
| I5 | 低 | **使っていない画像アセットが残っている** | `boost` / `like` / `nope` / `reload` / `superlike` の imageset は、どこからも使われていません |
| I6 | 低 | **Firebase Analytics のイベントを送っていない** | 初期化しているだけです。スワイプ数や、いいね率などのイベントを設計してください |
| I7 | 低 | **文字列がローカライズされていない** | 日本語の文字列をコードに直接書いています。String Catalog（Localizable.xcstrings）に移すと、英語対応が楽になります |
| I8 | 低 | **iPad、ダークモード、Dynamic Type の見た目を確認していない** | 動作を確認したのは、iPhone のライトモードだけです |

## 4. 不足している機能

| # | 優先度 | 機能 | 内容 |
| --- | --- | --- | --- |
| F1 | 中 | **おすすめ順** | 今はランダムに並べています。「好きなジャンル」の集計を使って、好みに近い作品を先に出すと、アプリの価値が大きく上がります |
| F2 | 中 | **ジャンルなどでデッキを絞り込む** | 「恋愛だけ」「完結済みだけ」などで絞り込めません |
| F3 | 中 | **作品を読む・買う場所へのリンク** | 気に入った作品の次の行動（電子書籍ストア、公式サイト）がありません。収益化の入り口にもなります |
| F4 | 中 | **初めて使う人への説明** | スワイプの方向の意味（右、左、上）を初回に説明する画面がありません |
| F5 | 低 | **詳細シートから判定する** | 詳細を開いたあと、閉じないと判定できません |
| F6 | 低 | **お気に入りの並び替えと編集** | 新しい順で固定です。いいねとスーパーいいねの切り替えもできません |
| F7 | 低 | **共有** | 気に入った作品を ShareLink で共有できません |
| F8 | 低 | **バックアップと引き継ぎ** | 履歴は端末の中だけです。iCloud（SwiftData の CloudKit 同期）やアカウント連携がありません |
| F9 | 低 | **ウィジェットと通知** | 「今日のおすすめ」ウィジェットや、新しい作品の通知がありません |
| F10 | 低 | **広告や課金** | 収益化の仕組みがありません。スーパーいいねの回数制限（Tinder 型）なども検討できます |

## 5. 対応した課題（記録）

| 内容 | 対応 |
| --- | --- |
| 飛ばしたカードが画面外に残り、一周するとデッキが壊れる | アニメーションが終わってからデッキを更新するように変更 |
| ドラッグの処理が重複していた | `SwipeDeckViewModel` にまとめた |
| View の body の中で ViewModel を作り直していた | `CacarrotApp` で 1 つだけ作り、environment で渡すように変更 |
| DRAGON BALL の作者が間違っていた | 修正（今はプレビュー用のサンプルのみ） |
| フォルダが他のアプリより 1 段深かった | `Cacarrot.xcodeproj` と `Cacarrot/` をトップに置く構成に変更 |
| サンプル 6 件のみだった | `manga_info.csv` から 500 件を同梱 |
