# 課題と不足している機能

2026-11-16 時点の実装をもとにまとめています。優先度の目安は次のとおりです。

| 優先度 | 意味 |
| --- | --- |
| 高 | リリース前に必要 |
| 中 | 使い勝手に大きく関わる |
| 低 | あるとよい |

## 1. リリース前に必要なこと（優先度：高）

| # | 内容 | 補足 |
| --- | --- | --- |
| H1 | **AniList のデータと画像を使ってよいか確認する**（楽天ブックスへ移行中） | AniList の API 規約では、商用利用に制限があります。同梱したあらすじと表紙画像の権利は、出版社や作者にあります。楽天ブックスAPIへの切り替えを進めています（取得・変換スクリプトとアプリ側は実装済み。楽天のサーバ停止中のため、実データは未取得）。ジャンルは引き続き AniList の値を使うため、その扱いも確認してください |
| H2 | **プライバシーマニフェスト（PrivacyInfo.xcprivacy）がない** | Firebase Analytics を組み込んでいるため、App Store の審査で必要です。App Privacy の申告も必要です |
| H3 | **`GoogleService-Info.plist` がないとアプリが落ちる** | Git の管理外なので、クローンしただけではビルドしても起動時に落ちます。ファイルがないときは `FirebaseApp.configure()` を呼ばないようにするか、設定方法をチームで共有してください |

## 2. データの課題

楽天モードで新しく出てくる確認事項があります。

| # | 優先度 | 内容 | 補足 |
| --- | --- | --- | --- |
| R1 | 高 | **楽天の実データで変換結果を確認する** | 作品のまとめ方（巻数表記の揺れ、外伝が別作品になるか）、あらすじの販売文言、楽天の区分コード（`RAKUTEN_GENRE_JA`）、表紙の `_ex=600x600` が効くかを確認する |
| R2 | 中 | **自宅のIPが変わると取得できなくなる** | 楽天の新仕様では、登録したIPからしか呼べません。`--check` で 403 になったらIPを登録し直してください |
| R3 | 低 | **AniList と一致しない作品はジャンルが楽天の区分だけになる** | タイトルの表記が違うと突き合わせに失敗します。一致率を見て、ローマ字タイトルでも突き合わせるか判断してください |


| # | 優先度 | 内容 | 補足 |
| --- | --- | --- | --- |
| D1 | 中 | **あらすじが英語、作者名がローマ字** | AniList のデータが英語のためです。楽天モードに切り替えると解決します（実データ待ち） |
| D2 | 中 | **中国の作品が少し混じる**（19天、長歌行 など） | CSV に国の情報がないため、タイトルの文字で判定しています。楽天モードでは、楽天ブックスで扱っているコミックだけになるので解決します（実データ待ち） |
| D3 | 中 | **作者が「スタッフの 1 人目」** | 原作者と作画者を区別していません。楽天モードでは、楽天の著者欄の1人目（通常は原作者）を使います（実データ待ち） |
| D5 | 低 | **お気に入りのデータが古くなる** | `SwipeRecord` は判定したときの作品情報のコピーを持っています。`manga.json` を作り直しても、お気に入り一覧は更新されません |
| D6 | 低 | **以前のサンプル（ID 0〜5）の履歴が残る** | 実データに切り替える前に判定した ONE PIECE などが、お気に入りに残っています。マイページのリセットで消えます。リリース時は関係ありません |
| D7 | 低 | **データの更新にアプリの再リリースが必要** | 作品はアプリに同梱しています。新しい作品を届けるには、Firestore などのリモートの取得元（`MangaRepository` の別実装）が必要です |
| D8 | 低 | **`query.py` の再開ページを手で書き換える** | `start_page = 1995` がコードに直接書かれています。最後に取得したページをファイルに保存し、引数で指定できるようにすると安全です |
| D9 | 低 | **ジャンルの日本語訳が一部だけ** | `GENRE_JA` にないジャンルは英語のまま表示されます |

## 3. 実装の課題

| # | 優先度 | 内容 | 補足 |
| --- | --- | --- | --- |
| I9 | 低 | **保存失敗時の動きを自動テストしていない** | 保存に失敗する状況をテストで作れないため、アラート表示とカードを戻す処理は未検証です。`SwipeHistoryStore` をプロトコルにして、失敗する偽物を差し込めるようにすると確認できます |
| I10 | 低 | **画面（UI）のテストがない** | 単体テストは ViewModel とサービスだけです。スワイプ操作や画面遷移は手動で確認しています |
| I4 | 低 | **マイページの集計を毎回すべての履歴で計算している** | 判定が数千件になると重くなる可能性があります。おすすめ順の計算（10枚ごとに全履歴を読む）も同じです。`fetchCount` を使うか、ジャンルの好み度をキャッシュしてください |
| I6 | 低 | **Firebase Analytics のイベントを送っていない** | 初期化しているだけです。スワイプ数や、いいね率などのイベントを設計してください |
| I7 | 低 | **文字列がローカライズされていない** | 日本語の文字列をコードに直接書いています。String Catalog（Localizable.xcstrings）に移すと、英語対応が楽になります |
| I8 | 低 | **iPad、ダークモード、Dynamic Type の見た目を確認していない** | 動作を確認したのは、iPhone のライトモードだけです |

## 4. 不足している機能

| # | 優先度 | 機能 | 内容 |
| --- | --- | --- | --- |
| F2 | 低 | **ジャンル以外での絞り込み** | ジャンルでの絞り込みは対応済みです。「完結済みだけ」「新しい作品」などは、データに連載状況や発売日を入れる必要があります（楽天データの `salesDate` が使えます） |
| F3 | 中 | **作品を読む・買う場所へのリンク** | 気に入った作品の次の行動（電子書籍ストア、公式サイト）がありません。詳細シートに「楽天ブックスで見る」ボタンを追加済みです（楽天データのときだけ表示）。アフィリエイトIDを設定すると収益化できます |
| F6 | 低 | **お気に入りの並び替えと編集** | 新しい順で固定です。いいねとスーパーいいねの切り替えもできません |
| F8 | 低 | **バックアップと引き継ぎ** | 履歴は端末の中だけです。iCloud（SwiftData の CloudKit 同期）やアカウント連携がありません |
| F9 | 低 | **ウィジェットと通知** | 「今日のおすすめ」ウィジェットや、新しい作品の通知がありません |
| F10 | 低 | **広告や課金** | 収益化の仕組みがありません。スーパーいいねの回数制限（Tinder 型）なども検討できます |

## 5. 対応した課題（記録）

| 内容 | 対応 |
| --- | --- |
| 飛ばしたカードが画面外に残り、一周するとデッキが壊れる | アニメーションが終わってからデッキを更新するように変更 |
| ドラッグの処理が重複していた | `SwipeDeckViewModel` にまとめた |
| View の body の中で ViewModel を作り直していた | `CacarrotApp` で 1 つだけ作り、environment で渡すように変更 |
| DRAGON BALL の作者が間違っていた | 修正（今はプレビュー用のサンプルのみ） |
| フォルダが他のアプリより 1 段深かった | `Cacarrot.xcodeproj` と `Cacarrot/` をトップに置く構成に変更 |
| サンプル 6 件のみだった | `manga_info.csv` から 500 件を同梱 |
| 表紙が毎回ネットワークから読み込まれていた（D4） | `ImageLoader` を追加。メモリとディスクの2段キャッシュ、上から6枚の先読み、失敗時の再読み込みボタン（2026-11-16） |
| カードがランダムに並ぶだけだった（F1） | `RecommendationEngine` を追加。ジャンルの好み度順に並べ、4枚に1枚は好みから外れた作品を混ぜる。マイページでオン・オフ可能（2026-11-16） |
| Git リポジトリがなかった | `carrot-99/Cacarrot` を作成して push（2026-11-16） |
| ジャンルで絞り込めなかった（F2） | `GenreFilterView` を追加。複数ジャンルのいずれかを含む作品に絞り込み、選択を保存（2026-11-16） |
| 使い方の説明がなかった（F4） | `SwipeGuideView` を追加。初回起動時に表示し、マイページから再表示できる（2026-11-16） |
| 詳細シートから判定できなかった（F5） | デッキから開いた詳細シートの下部に判定ボタンを追加（2026-11-16） |
| `"nope"` の直書き（I3）・使っていない画像（I5） | `SwipeRecord.likedPredicate` にまとめた。`boost` など 5 つの imageset を削除（2026-11-16） |
| アプリのテストがなかった（H5） | `CacarrotTests` ターゲットと共有スキームを追加。単体テスト22件（2026-11-16） |
| 取り消し履歴が保存されなかった（I1） | 保存済みの判定から最大20件を復元し、再起動後も取り消せるようにした（2026-11-16） |
| 保存の失敗に気づけなかった（I2） | 失敗時は rollback してアラートを表示し、カードを元に戻す（2026-11-16） |
| 共有できなかった（F7） | 詳細シートに ShareLink を追加（2026-11-16） |
| 楽天ブックスへの切り替え準備 | `fetch_rakuten.py`、`build_app_data.py --source rakuten`、詳細シートの購入リンク、マイページのクレジット表記を追加（2026-11-16） |
